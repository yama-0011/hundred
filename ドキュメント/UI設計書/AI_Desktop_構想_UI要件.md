# AI Desktop 構想・UI要件

## 1. プロジェクト概要
生成AI駆動開発について体系的に学べるWebサービスを作成する。

一般的な技術ブログにはせず、Windowsのデスクトップ環境をモチーフとした **「AI Desktop」** というUIを採用する。
生成AI関連サービス・ツールをWindowsアプリケーションのように扱い、ユーザーが各アプリを起動して、そのサービスについて学習する構成とする。

## 2. 主目的
1. 生成AI駆動開発について体系的に学習できる
2. 自分自身の学習記録・ナレッジとして利用できる
3. 一般的な技術ブログとは異なる、触っていて面白いUIを提供する
4. 将来的にユーザーごとのカスタマイズを可能にする
5. 公開コンテンツとしてSEOにも対応できる構造にする

## 3. 掲載予定サービス・ツール
現時点：
- ChatGPT
- Codex
- Claude Code

将来的な候補：
- GitHub Copilot
- Gemini系ツール
- その他AI Coding Agent

## 4. AI Desktop
WindowsのデスクトップをベースとしたUIとする。
Windowsを完全コピーするのではなく、Windows利用者が直感的に操作できる「WindowsライクなWebデスクトップ」を目指す。

```text
┌───────────────────────────────────────────────┐
│  ChatGPT        Codex        Claude Code      │
│                                               │
│  Explorer       Settings                      │
│                                               │
├───────────────────────────────────────────────┤
│ Start                                    14:30│
└───────────────────────────────────────────────┘
```

## 5. AIサービスの扱い
ChatGPT、Codex、Claude Codeなどはフォルダではなく、UI・概念上の **アプリケーション（exe）** として扱う。

```text
ChatGPT.exe
Codex.exe
ClaudeCode.exe
```

デスクトップ上のショートカットをダブルクリックすると対象アプリのウィンドウが開く。

## 6. exe間のUI共通化
サービスごとの専用UIは作成せず、基本レイアウト・コンポーネントを共通化する。

サービスごとの差異：
- アプリ名
- アイコン
- アクセントカラー
- カテゴリ
- コンテンツ

新しいサービスを追加するたびに専用画面を実装する構造にはしない。

## 7. exeトップ（カテゴリ）画面
exeを起動すると対象サービスのカテゴリ一覧を表示する。

カテゴリ数は有限であり、大量データ向けのページング等は考慮不要。

UIは **Windowsの「設定」画面** を参考にする。

```text
┌─ Codex ─────────────────────────────────────────┐
│  Codex                         [ Codex内を検索 ] │
│                                                │
│       基本知識          開発環境          モデル │
│     Codexとは？       Local / IDE      選択・推論 │
│                                                │
│       AI駆動開発        機能・連携       料金・利用量│
│      開発での活用       MCP / Git      Credit / 制限│
└────────────────────────────────────────────────┘
```

各カテゴリは以下を持つ。
- アイコン
- カテゴリ名
- 短い説明

余白を広く取り、大量の情報を詰め込まない。

## 8. カテゴリ
カテゴリ内容は未確定。

Codexの仮例：

```text
Codex
├── 基本知識
├── 開発環境
├── モデル
├── 機能・連携
├── 料金・利用量

```

生成AI駆動開発について調査・学習しながら正式決定する。

## 9. カテゴリ詳細
**「左ペイン + コンテンツ」の構成で確定。**

「カテゴリ → 記事一覧 → 記事詳細」という3階層にはせず、カテゴリ詳細そのものにコンテンツを表示する。

```text
┌────────────────┬─────────────────────────────────┐
│ 料金・利用量    │ Creditとは                      │
│                │                                 │
│ Overview       │ ──────────────────────────────  │
│ Plans          │                                 │
│ Credits   ●    │ 本文                            │
│ Limits         │                                 │
│ Usage          │ 画像 / コード / 表など           │
└────────────────┴─────────────────────────────────┘
```

左ペイン：
- カテゴリ内コンテンツ一覧
- 現在選択中の項目
- 必要に応じてカテゴリ概要

右ペイン：
- タイトル
- 本文
- 画像
- コード
- 表
- その他技術コンテンツ

## 10. 「記事」という概念
UI上では「記事」という単位を強く見せない。

```text
Codex
└── 料金・利用量
    ├── Overview
    ├── Plans
    ├── Credits
    ├── Limits
    └── Usage
```

ユーザーには「記事を読む」より **「Codexの料金・利用量について調べている」** と感じられる体験を目指す。

## 11. Explorer
AI DesktopにはExplorerを用意する。
記事や画像等のコンテンツをWindows Explorer風UIで管理・閲覧する構想。

```text
AI Desktop
├── Articles
│   ├── ChatGPT
│   ├── Codex
│   └── Claude Code
└── Images
    ├── ChatGPT
    ├── Codex
    └── Claude Code
```

ExplorerはUI上の表現であり、バックエンドまでWindowsの物理フォルダ構造を再現する必要はない。

## 13. SEO
SEO対応は行うが、SEO目的の記事量産サイトにはしない。
目的はあくまで「生成AI駆動開発について学習できるサービス」。

各コンテンツには個別URLを持たせる想定。

```text
/codex
/codex/models
/codex/cost/credits
/codex/development/local-repository
```

検索から個別コンテンツへ直接アクセスした場合も、AI Desktop / exeの世界観を維持して表示できる構造を検討する。

## 14. UI階層
```text
AI Desktop
    ↓
AIサービスのショートカット
    ↓
exe起動
    ↓
カテゴリ一覧
    ↓
カテゴリ詳細
    ↓
左ペインからコンテンツ切替
```

例：

```text
AI Desktop
    ↓
Codex.exe
    ↓
Codex Home
    ↓
料金・利用量
    ↓
Credits
```

カテゴリ詳細と記事詳細を別画面にはしない。

## 15. UI設計方針
重視：
- Windowsライクで直感的
- 一般的な技術ブログとは異なるUI
- 可読性
- exe間でのUI統一
- コンポーネント再利用
- AIサービスを追加しやすい
- カスタマイズ性
- SEOとの両立

避ける：
- サービスごとに完全に異なるUI
- 保守コストが極端に高い作り込み
- 読みにくくなる奇抜なUI
- 大量データ前提の複雑な一覧処理
- Windowsの完全コピー
