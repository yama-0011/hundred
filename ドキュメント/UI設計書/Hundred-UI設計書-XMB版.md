# Hundred UI設計書

## 1. UIコンセプト

Hundredはスマートフォン利用を中心とした、複数のAppを利用するためのプラットフォームである。

Hundred
Homeは、従来検討していた「4列×6行のiPhone風ホーム画面」方式を採用せず、**横方向にカテゴリ、縦方向にカテゴリ内の項目を配置するXMB型UI**を採用する。

PSPのホーム画面のような「横×縦」の直感的な操作感を参考にしつつ、Hundred独自のUIとして構成する。

基本方針：

-   スマートフォンファースト
-   PWA利用を想定
-   横方向 = Hundredの主要カテゴリ
-   縦方向 = 選択中カテゴリの項目
-   選択中のカテゴリ・項目を視覚的に明確化
-   不要な情報を常時表示しない
-   Light / Darkに対応
-   各カテゴリの詳細画面は必要に応じて個別設計する

------------------------------------------------------------------------

## 2. Hundred Home

### 2.1 基本レイアウト

Hundred Homeの横方向には、以下の5カテゴリを配置する。

1.  Profile
2.  Apps
3.  Store
4.  Mail
5.  Settings

基本イメージ：

``` text
Hundred
━━━━━━━━━━━━━━━━━━━━━━

 Profile    Apps    Store    Mail    Settings
             │
             ● Record Hub
             ○ Memo
             ○ Game
```

横方向でカテゴリを選択し、選択したカテゴリに複数の項目が存在する場合は、そのカテゴリの縦方向に項目を展開する。

------------------------------------------------------------------------

## 2.2 横方向のカテゴリ移動

横方向にはHundredの主要カテゴリを並べる。

``` text
Profile  ←→  Apps  ←→  Store  ←→  Mail  ←→  Settings
```

スマートフォンでは横方向のスワイプ操作を基本とする。

カテゴリを切り替えた場合、画面中央付近の選択位置を基準として、選択中カテゴリが分かるように表示する。

具体的なアニメーション速度、慣性、アイコンサイズ等は実装時に調整する。

------------------------------------------------------------------------

## 2.3 縦方向の項目移動

選択中カテゴリに複数の項目が存在する場合、縦方向に項目を配置する。

Appsカテゴリの例：

``` text
              Apps
               │
               ● Record Hub
               ○ Memo
               ○ Game
               ○ ...
```

スマートフォンでは縦方向のスワイプ操作を基本とする。

選択中の項目は、サイズ・透明度・位置・マーカー等を用いて他の項目より強調する。

具体的な強調表現は実装時に調整する。

------------------------------------------------------------------------

# 3. 各カテゴリ

## 3.1 Profile

Hundredのユーザー情報にアクセスするためのカテゴリとする。

ログイン・認証機能は後回しとしているため、初期段階では詳細UIを確定しない。

将来的には以下の情報・機能を配置可能とする。

-   ユーザー情報
-   アカウント情報
-   Google連携情報

------------------------------------------------------------------------

## 3.2 Apps

HundredにインストールされているUser Appsを表示するカテゴリとする。

例：

``` text
Apps
 │
 ├─ Record Hub
 ├─ Memo
 ├─ Game
 └─ ...
```

Appを選択すると対象Appを起動する。

Record
HubはHundredのSystem機能ではなく、StoreからユーザーがインストールするUser
Appとして扱う。

Hundredのコンセプト上、User Appsは最大100 Appsまで扱えるものとする。

### 新規App

Storeで新しいAppをインストールした場合、Appsカテゴリの末尾へ追加する。

### Appの並び順

Appsカテゴリ内の具体的な並び替え操作については、XMB型UIへの変更に伴い再検討対象とする。

従来の「ホーム画面長押し →
アイコンをドラッグ」という4×6ホーム向け仕様は廃止する。

------------------------------------------------------------------------

## 3.3 Store

Hundredで利用可能なUser
Appを探し、インストール・管理するカテゴリとする。

Storeを選択するとHundred Store画面へ遷移する。

Store画面自体は、これまで決定した**シンプルな一覧型UI**を維持する。

------------------------------------------------------------------------

## 3.4 Mail

Hundredからユーザーへの情報提供を行うカテゴリとする。

想定用途：

-   Hundredのアップデート情報
-   各Appのアップデート情報
-   メンテナンス情報
-   Hundredからのお知らせ
-   重要なお知らせ

Mailの詳細UIは後続フェーズで設計する。

------------------------------------------------------------------------

## 3.5 Settings

Hundred共通設定へアクセスするカテゴリとする。

初期版では以下を用意する。

### 表示

-   Light
-   Dark

### アカウント

-   サインアウト

将来的にGoogle連携情報等を追加可能な構成とする。

------------------------------------------------------------------------

# 4. Hundred Store

## 4.1 基本構成

Storeはシンプルな一覧型UIとする。

Store画面下部には以下の3タブを配置する。

``` text
アプリ      ランキング      My Apps
```

------------------------------------------------------------------------

## 4.2 アプリタブ

Hundredで利用可能なAppを縦一覧で表示する。

``` text
🗂 Record Hub
記録を自由に管理
                         [入手]

📝 Memo
シンプルなメモ
                         [入手]

🎮 Game
ゲーム
                         [入手]
```

各Appには最低限以下を表示する。

-   Appアイコン
-   App名
-   短い説明
-   入手 / 開く

インストール済みの場合は「入手」ではなく「開く」を表示する。

App名またはアイコンを押下するとApp詳細画面へ遷移可能とする。

「入手」押下時はApp詳細画面を必須経由とせず、その場でインストールを開始する。

------------------------------------------------------------------------

## 4.3 ダウンロード演出

「入手」押下後、Appをダウンロード・インストールしているような演出を表示する。

これはHundredの遊び心を表現するUI演出とする。

例：

``` text
🗂 Record Hub

        ◯  0%
        ◔  30%
        ◑  70%
        ● 100%

     インストール完了

        [ 開く ]
```

円形プログレス等、ダウンロードを連想させる表現を採用する。

実処理が短時間で完了する場合でも、不自然な長時間待機は行わない。

インストール完了後、対象AppをHundred HomeのAppsカテゴリ末尾へ追加する。

------------------------------------------------------------------------

## 4.4 ランキングタブ

Hundred Appの人気順位をシンプルな一覧形式で表示する。

``` text
ランキング

1  Record Hub
2  Memo
3  Game
4  ...
```

App数が少ない初期段階では実装を後回しにしてもよい。

------------------------------------------------------------------------

## 4.5 My Appsタブ

ユーザーがインストールしているUser Appsを一覧表示する。

``` text
My Apps

🗂 Record Hub
インストール済み
                         [開く]

📝 Memo
インストール済み
                         [開く]
```

My Appsから以下の管理を行える構成とする。

-   Appを開く
-   アンインストール
-   App情報の確認
-   将来的なAppデータ管理
-   Appデータの完全削除

------------------------------------------------------------------------

## 4.6 App詳細

App詳細画面は情報確認用とし、「入手」のための必須画面とはしない。

想定表示：

-   Appアイコン
-   App名
-   概要
-   バージョン
-   更新日
-   更新履歴
-   入手 / 開く

詳細項目は実装時に必要性を確認する。

------------------------------------------------------------------------

# 5. Appインストール

Record Hubを含むUser Appは初期状態で自動インストールしない。

初回チュートリアルでは、StoreからRecord
Hubをインストールする操作を利用してHundredの基本操作を体験させる。

想定フロー：

``` text
Hundredへようこそ
      ↓
Storeへ移動
      ↓
Record Hub
[ 入手 ]
      ↓
ダウンロード演出
      ↓
Appsカテゴリへ追加
      ↓
Record Hubを起動
```

------------------------------------------------------------------------

# 6. Appアンインストール

通常のアンインストールではAppの利用状態のみ解除し、App内のユーザーデータは保持する。

再インストールした場合、保持されているデータを再利用できる。

アンインストール前には確認画面を表示する。

``` text
Record Hubをアンインストールしますか？

Record HubのデータはHundredに保持されます。
再インストールすると引き続き利用できます。

[キャンセル] [アンインストール]
```

Appデータの完全削除は通常のアンインストールとは分離する。

完全削除はStoreのMy Apps側から実行可能とする。

XMB型Home上からのアンインストール操作方法については、操作UIを実装する段階で再検討する。

------------------------------------------------------------------------

# 7. 初回表示

初回状態ではUser Appを自動配置しない。

Appsカテゴリは空の状態から開始する。

``` text
Hundred
━━━━━━━━━━━━━━━━━━━━━━

 Profile    Apps    Store    Mail    Settings
             │
             ○ Appはまだありません
```

チュートリアルによってStoreへ誘導し、Record Hubを最初のUser
Appとしてインストールさせる。

------------------------------------------------------------------------

# 8. Light / Dark

Hundred共通UIはLight / Darkの2テーマを初期対応とする。

Settingsから切り替え可能とする。

XMB型Homeの背景・文字・選択状態・アイコン等もテーマに応じて視認性を維持する。

具体的な配色は実装時に決定する。

------------------------------------------------------------------------

# 9. レスポンシブ方針

スマートフォン表示を基準とする。

Hundred
Homeは横方向・縦方向の操作を中心とするため、端末サイズに応じて以下を調整する。

-   カテゴリ間隔
-   App間隔
-   アイコンサイズ
-   文字サイズ
-   選択位置
-   表示する前後項目数

PCブラウザではキーボード・マウス操作への対応も将来的に検討可能とする。

具体的なブレークポイントは実装時に決定する。

------------------------------------------------------------------------

# 10. 端末ホーム連携

「端末ホーム連携」は機能として将来実装する方針を維持する。

ただし、XMB型Homeへの変更により、従来の「下部固定4枠」の4つ目として表示する仕様は廃止する。

Hundred
Home上での配置場所および導線は、端末ホーム連携機能を詳細設計する際に改めて決定する。

Web/PWAの制約上、Hundredが端末ホームへ完全自動でAppアイコンを追加することは前提としない。

------------------------------------------------------------------------

# 11. UI状態

最低限、以下の状態を考慮する。

-   User Appなし
-   User Appあり
-   Appインストール中
-   Appインストール済み
-   Appアンインストール確認
-   横カテゴリ選択
-   縦項目選択
-   Light
-   Dark
-   Store一覧取得中
-   Store一覧取得失敗

詳細なエラー表示・アニメーションは実装時に決定する。

# 13. Record HubとのUI境界

Hundred HomeのAppsカテゴリからRecord Hubを選択するとRecord Hub
Appへ遷移する。

Record Hub内部の以下のUIはHundred UI設計書では定義しない。

-   Life Hub
-   Collections
-   Records
-   Record Hub固有設定
-   Record Hub内の編集モード

これらはRecord Hub専用UI設計書で管理する。

HundredはAppの入口・Store・共通基盤に責務を限定する。

------------------------------------------------------------------------

# 14. 旧4×6ホーム仕様の扱い

以前検討した以下のHundred Home仕様は、本UI設計への変更に伴い廃止する。

-   4列×6行のAppグリッド
-   最大4ページのホーム画面
-   ページインジケーターによるAppページ管理
-   下部固定4 App領域
-   Store / Mail / 設定 / 端末ホーム連携を下部4枠に固定する構成
-   iPhone風の長押しアイコン編集をHundred Homeの基本操作とする仕様

最大100 AppsというHundredのコンセプト自体は維持する。
