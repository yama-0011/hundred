# フロントエンド コメント実装ルール

## 1. 目的

React / TypeScriptを学び始めた開発者でも、ファイルと処理の役割をコードから追える状態を保つ。

コメントには、コードを日本語へ置き換えただけの説明ではなく、次の内容を記述する。

- 何のために存在するか
- 何を担当するか
- コードだけでは判断しにくい設計上の理由や制約

## 2. 基本ルール

1. コメントは日本語で記述する。
2. ファイル単位で「概要」と「責務」を記述する。
3. 名前を付けて定義したコンポーネント、関数、メソッド、カスタムHookには「概要」と「責務」を記述する。
4. コードを読めば明らかな処理を、行単位で説明しない。
5. 実装を変更した場合は、関連するコメントも同時に更新する。
6. コメントと実装が異なる場合は、実装だけでなくコメントも不具合として扱う。
7. 「責務外」の欄は設けない。

## 3. ファイル単位のコメント

import文より前、またはimport文の直後に記述する。

```ts
/**
 * 概要:
 * Hundred Homeのカーソル音を選択するダイアログを表示する。
 *
 * 責務:
 * - 利用可能なカーソル音を一覧表示する
 * - 現在選択中の音を示す
 * - 選択、試聴、閉じる操作を親へ通知する
 */
```

### 概要に書くこと

- ファイルが何を提供するか
- どの画面または機能で使用するか

### 責務に書くこと

- ファイルが担当する主要処理
- 状態管理、描画、外部通信などの役割

責務が1つの場合でも、省略せず記述する。

## 4. コンポーネント・関数・メソッド単位のコメント

定義の直前へ記述する。

```ts
/**
 * 概要: 保存済みのカーソル音を読み込む。
 * 責務: 保存値を検証し、利用可能な音源IDを返す。
 */
function getInitialCursorSound(): CursorSoundId {
  // 実装
}
```

Reactコンポーネントも同じ形式を使用する。

```tsx
/**
 * 概要: Hundred HomeのXMB型UIを表示する。
 * 責務: カテゴリとAppの選択状態、および各入力操作を管理する。
 */
function HundredHome() {
  // 実装
}
```

複数の責務がある場合は箇条書きにする。

```ts
/**
 * 概要: カーソル移動音を再生する。
 *
 * 責務:
 * - 選択中の音源を取得する
 * - 音声バッファを準備する
 * - 連続入力ごとに独立した再生ノードを開始する
 */
function playCursorSound() {
  // 実装
}
```

## 5. 対象となる処理

次の名前付き処理にはコメントを付ける。

- Reactコンポーネント
- 通常関数
- イベントハンドラー
- カスタムHook
- クラスのメソッド
- データ変換や検証を行うヘルパー関数

次のような短いインライン処理には、原則としてコメントを付けない。

```tsx
onClick={() => onSelect(sound.id)}
```

説明が必要なほど複雑な場合は、名前付き関数として抽出してからコメントを付ける。

## 6. 処理内部のコメント

処理内部では「なぜその処理が必要か」がコードだけでは判断しにくい場合に記述する。

良い例:

```ts
// iPhoneでは同じ音声要素の連続再生が中断されるため、再生ノードを毎回生成する。
source.start()
```

避ける例:

```ts
// 音量を設定する。
gain.gain.value = volume
```

## 7. 型・定数・設定データのコメント

型名や変数名だけでは用途が判断しにくい場合に記述する。

```ts
// ファイル名変更前の保存値を、現在の音源IDへ読み替える。
const legacyCursorSoundIds = {
  move: 'game',
}
```

設定値には、単位、推奨範囲、並び順などの入力条件を記述する。

```ts
volume: 0.65, // 基準音量。通常は0〜1程度を指定する。
```

## 8. CSSのコメント

CSSファイルにも、ファイル単位の「概要」と「責務」を記述する。

```css
/**
 * 概要:
 * Hundred Homeのカーソル音選択画面を装飾する。
 *
 * 責務:
 * - 選択ダイアログのレイアウトを定義する
 * - 音源の選択状態とフォーカス状態を表現する
 */
```

スタイルのまとまりごとにブロックコメントを記述する。

```css
/* --------------------------------------------------------------------------
 * 音源一覧
 * 各音源の説明と選択状態を、操作可能な行として表示する。
 * -------------------------------------------------------------------------- */
```

セレクターやCSSプロパティを1行ずつ説明するコメントは記述しない。

## 9. コメント更新チェック

実装変更時に次を確認する。

- ファイルの概要と実際の用途が一致しているか
- 責務に不足または過去の機能が残っていないか
- 関数名、保存キー、画面名などが古いままではないか
- 設計上の理由が現在も有効か
- 削除した機能のコメントが残っていないか
