# Webアプリケーション技術 復習計画

## 1. 目的

個人開発で使用した技術について、単に「使用したことがある」状態から、仕組み・採用理由・処理の流れを説明し、小規模な機能を自力で再現できる状態へ理解を深める。

本計画では、既存のWebアプリケーションを実践教材として使用し、次の流れで復習する。

```text
公式資料で基礎を確認する
  ↓
既存コード内の使用箇所を探す
  ↓
画面・API・DB間の処理を追う
  ↓
小規模な修正または再実装を行う
  ↓
正常時・異常時の挙動を確認する
  ↓
自分の言葉で仕組みを説明する
```

特定日までのアプリケーション完成は目的としない。待機期間の長さにかかわらず、現在取り組んでいるテーマを一区切りとして終了できる構成とする。

---

## 2. 対象技術

| 分類 | 対象技術 | 復習の重点 |
|---|---|---|
| 言語 | TypeScript / Java / SQL / HTML / CSS | 文法だけでなく、既存処理を説明・修正できる状態を目指す |
| フレームワーク・ライブラリ | React / Spring Boot / Vite / AWS Amplify | 各技術の役割と処理の流れを理解する |
| DB | PostgreSQL / SQLite（Cloudflare D1） | テーブル設計、SQL、制約、トランザクションを復習する |
| クラウド | AWS / Cloudflare | 各サービスの責務、通信経路、障害時の影響を理解する |
| OS | macOS / Linux | 基本コマンド、プロセス、ログ、権限、環境変数を確認する |
| 開発・管理ツール | Git / GitHub / VS Code / npm / Maven / Wrangler | 開発、ビルド、デプロイの操作を理解する |
| その他 | REST API / OAuth 2.0 / OpenID Connect / JWT / 外部API | 認証、API通信、エラー処理、セキュリティを復習する |

---

## 3. 復習できたと判断する基準

各技術について、次の項目を満たした場合に一区切りとする。

- [ ] 何のために使用する技術か説明できる
- [ ] 既存アプリケーション内の使用箇所を示せる
- [ ] 入力から出力までの処理の流れを説明できる
- [ ] 関連する設定ファイルや環境変数を説明できる
- [ ] エラー発生時に確認するログや箇所を判断できる
- [ ] 小規模な処理を自分で修正または再実装できる
- [ ] 正常時と代表的な異常時の挙動を確認できる

すべてを暗記することは目的としない。必要な情報を公式資料や既存コードから調べ、根拠を持って判断できる状態を重視する。

## 5. 学習計画1：Java / Spring Boot

### 5.1 目標

JavaとSpring Bootを使用したAPIについて、起動からリクエスト受付、業務処理、DBアクセス、レスポンス返却までの流れを説明できるようにする。

### 5.2 実施内容

| 項目 | 取り組む内容 |
|---|---|
| Java基礎 | クラス、インターフェース、継承、カプセル化、コレクション、例外処理を復習する |
| Spring Boot | 起動処理、Bean、DI、アノテーション、設定ファイルの役割を確認する |
| レイヤー | Controller / Service / Repository / DTO / Entityの責務を確認する |
| API | GET / POST / PUT / DELETE、リクエスト、レスポンス、HTTPステータスを確認する |
| 入力検証 | 必須、文字数、形式、不正値に対するバリデーションを確認する |
| 例外処理 | 業務エラーとシステムエラーの扱い、例外ハンドラーを確認する |
| 実践 | 小規模なCRUD APIを追加または再実装する |

### 5.3 進め方

- [ ] Javaの基本文法とオブジェクト指向を公式資料または書籍で復習する
- [ ] Spring Bootアプリケーションの起動クラスから処理を追う
- [ ] 既存APIを1本選び、ControllerからDB処理まで読み進める
- [ ] 使用されているアノテーションの意味を確認する
- [ ] 小規模なCRUD APIを実装する
- [ ] 正常入力、未入力、不正値、存在しないIDで挙動を確認する
- [ ] エラー時のログとレスポンスを確認する
- [ ] APIの処理をコードを見ずに説明する

## 6. 学習計画2：データベース・SQL・REST API

### 6.1 目標

PostgreSQLとSQLiteの違いを理解し、基本的なテーブル設計、SQL、マイグレーションおよびREST APIの設計を説明できるようにする。

### 6.2 実施内容

| 項目 | 取り組む内容 |
|---|---|
| DB基礎 | 主キー、外部キー、NOT NULL、UNIQUE、CHECK制約を復習する |
| テーブル設計 | 正規化、関連、履歴管理、状態管理を確認する |
| SQL | SELECT / INSERT / UPDATE / DELETE / JOIN / GROUP BYを復習する |
| 性能 | インデックスの目的と、検索条件との関係を確認する |
| トランザクション | commit / rollbackと整合性を確認する |
| マイグレーション | DDLの適用順序、再実行、失敗時の扱いを確認する |
| REST API | URL、HTTPメソッド、ステータス、リクエスト・レスポンスを設計する |

### 6.3 進め方

- [ ] 既存テーブルとマイグレーションを読み、テーブル間の関連を確認する
- [ ] 主キー、外部キー、制約、インデックスの設定理由を考える
- [ ] PostgreSQLとSQLiteで異なる型や機能を確認する
- [ ] CRUDとJOINを含むSQLを直接実行する
- [ ] API実行前後のDBデータを比較する
- [ ] トランザクション中にエラーが発生した場合の挙動を確認する
- [ ] 小規模なテーブルとAPIを設計・実装する
- [ ] APIの正常時・異常時のステータスとレスポンスを確認する

## 8. 学習計画4：認証・認可

### 8.1 目標

OAuth 2.0、OpenID Connect、JWTおよびCognitoを使用した認証について、各登場要素の役割とログイン処理の流れを説明できるようにする。

### 8.2 実施内容

| 項目 | 取り組む内容 |
|---|---|
| 基本概念 | 認証と認可の違いを確認する |
| OAuth 2.0 | Authorization Code Flow、state、PKCEを確認する |
| OpenID Connect | OAuth 2.0との違い、IDトークンの役割を確認する |
| JWT | Header / Payload / Signature、iss / aud / sub / expを確認する |
| Cognito | User Pool、App Client、Hosted UI、外部IdPの役割を確認する |
| Amplify | フロントエンドからCognitoを利用する処理を確認する |
| API保護 | API側のJWT検証とユーザー識別を確認する |
| 外部OAuth | WordPress・Instagram連携と利用者ログインの違いを確認する |

### 8.3 進め方

- [ ] サインインボタン押下からアプリへ戻るまでを追う
- [ ] ブラウザ、Cognito、外部IdP、APIの役割を整理する
- [ ] 認可コードとトークンの違いを確認する
- [ ] JWTをデコードし、主要なClaimを確認する
- [ ] API側の署名・issuer・audience・期限検証を確認する
- [ ] トークンなし、不正トークン、期限切れを想定して挙動を確認する
- [ ] stateとPKCEが防ぐ攻撃を確認する
- [ ] ログアウト時に削除・失効する情報を確認する
- [ ] 外部サービス用アクセストークンの保存方法を確認する

## 10. 外部API連携の横断復習

Gemini API、WordPress REST API、Instagram APIは、個別のサービス仕様だけでなく、共通するAPI連携の観点で復習する。

| 観点 | 確認内容 |
|---|---|
| 認証 | APIキー、OAuthアクセストークン、権限スコープの違い |
| リクエスト | URL、HTTPメソッド、Header、Query、Body |
| レスポンス | 成功データ、エラー形式、HTTPステータス |
| 制限 | レート制限、利用上限、料金、トークン有効期限 |
| 安全性 | シークレットをブラウザ・ログ・Gitへ出さない設計 |
| 障害対応 | タイムアウト、再試行、外部サービス停止時の扱い |
| 整合性 | 同じリクエストやイベントを重複反映しない仕組み |

### 10.1 進め方

- [ ] 各APIの公式ドキュメントで認証方式を確認する
- [ ] 既存のAPI呼び出し処理を1つずつ追う
- [ ] `curl`等で最小構成のリクエストを実行する
- [ ] 正常レスポンスとエラーレスポンスを比較する
- [ ] APIキーやトークンの保存場所を確認する
- [ ] タイムアウト・レート制限・期限切れ時の挙動を確認する
- [ ] 重複実行を防ぐ処理が必要な箇所を確認する

## 11. 1日の進め方

1日8時間を目安とする場合、次の配分を基本とする。

| 時間 | 内容 |
|---|---|
| 1時間 | 公式ドキュメント、書籍等による基礎確認 |
| 2時間 | 既存コード・設定・DB構造の確認 |
| 3時間 | 小規模な修正、再実装、コマンド実行 |
| 1時間 | 正常時・異常時の動作確認 |
| 1時間 | 不明点の再調査と理解状況の振り返り |

調査だけ、実装だけに偏らず、毎日少なくとも「読む・動かす・説明する」を1回ずつ行う。

各日の終了時に、次の項目を確認する。

- [ ] 今日扱った技術を説明できるか

- [ ] 正常時だけでなく異常時も確認したか

- [ ] 次に確認する内容を決めたか

## 13. 優先順位

優先順位は次のとおりとする。

1. Java / Spring Boot
2. SQL / DB / REST API
3. React / TypeScript
4. OAuth 2.0 / OpenID Connect / JWT
5. AWS / Cloudflare / Linux
6. 外部API固有の仕様

Java / Spring Boot、SQL、REST APIは実務経験との関連が強く、設計・実装・面談のいずれでも説明を求められる可能性が高いため、最初に理解を深める。

テスト技法だけを独立した学習テーマにはしない。ただし、各テーマで変更した処理について、正常時と代表的な異常時の確認は必ず行う。
