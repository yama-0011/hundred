# Hundred UI表記ルール

## 1. 目的

HundredおよびHundred上で提供する各プロダクトのUIについて、日本語と英語の使い分けを統一する。

本ルールでは、日本語を標準言語とし、ユーザーが画面を見たときに、機能の意味や操作結果を迷わず理解できることを優先する。

## 2. 適用範囲

本ルールは、次のユーザー向け表記に適用する。

- 画面名、機能名、メニュー名
- ボタン、リンク、タブ、入力項目
- 説明文、ヘルプ、確認メッセージ
- 状態、通知、エラーメッセージ
- ツールチップや`aria-label`などのアクセシビリティ用テキスト
- サインイン画面や初期設定画面

変数名、型名、ファイル名など、ソースコード内部の命名は対象外とし、別途定めるコーディング規約に従う。

## 3. 基本方針

> Hundredのユーザーインターフェースは日本語を標準とする。操作名、機能名、説明文および状態表示には日本語を使用し、製品名・サービス名・コンテンツ固有名・定着した略語のみ正式な英字表記を使用する。同じ概念には常に同じ表記を用いる。

表記に迷う場合は、原則として日本語を採用する。

## 4. 日本語で表記するもの

### 4.1 画面、機能、操作

ユーザーが操作の意味を判断するための言葉は日本語にする。

| 英語表記 | 採用する表記 |
| --- | --- |
| Home | ホーム |
| Profile | プロフィール |
| Apps | アプリ |
| Store | ストア |
| Mail | メール |
| Settings | 設定 |
| Wallpaper | 壁紙 |
| Sound | サウンド、または効果音 |
| Notifications | 通知 |
| Account | アカウント |

「サウンド」と「効果音」のように複数の候補がある場合は、対象範囲に合わせて使い分ける。画面全体の音に関する設定は「サウンド」、操作音だけを対象とする場合は「効果音」とする。

### 4.2 状態表示

状態は、現在の結果が直接伝わる日本語にする。

| 英語表記 | 採用する表記 |
| --- | --- |
| Selected | 選択中 |
| Connected | 接続済み |
| Enabled | 有効 |
| Disabled | 無効 |
| On / Off | オン / オフ |
| Loading | 読み込み中 |
| Coming soon | 準備中 |

### 4.3 入力項目とアカウント操作

| 英語表記 | 採用する表記 |
| --- | --- |
| Display name | 表示名 |
| Email | メールアドレス |
| Member ID | メンバーID |
| Sign in | サインイン |
| Sign up | アカウントを作成 |
| Sign out | サインアウト |
| Continue as guest | ゲストとして続ける |

「サインアップ」のような用語よりも、何が行われるかが明確な「アカウントを作成」を優先する。

### 4.4 説明文とメッセージ

説明文、確認文、エラー文は日本語で記述する。文中に固有名詞を含む場合は、固有名詞のみ正式表記を維持する。

例:

```text
Hundredへようこそ
Googleアカウントでサインイン
Record Hubで記録を確認する
```

## 5. 英字表記を使用するもの

次のいずれかに該当する場合に限り、英字表記を使用する。

### 5.1 製品名、サービス名、企業名

公式の表記を変更しない。

```text
Hundred
Record Hub
Google
```

### 5.2 定着した略語や規格名

日本語UIでも英字表記が一般的なものは、無理に翻訳しない。

```text
ID
URL
QRコード
Wi-Fi
```

### 5.3 コンテンツ固有の名前

壁紙、サウンド、ゲーム、作品などに付けられた名称は、コンテンツの正式名称を維持する。

```text
Mist
Midnight
Aurora
Block
Digital
Game
```

ただし、それらが固有名ではなく、単に機能を説明する言葉である場合は日本語にする。

### 5.4 表現そのものに意味がある演出

ゲーム内のロゴ、作品タイトル、装飾的な演出など、英語表記自体が体験の一部となる場合は例外とする。

ただし、操作に必要な情報を装飾的な英語だけで提供してはならない。

## 6. Hundredとホームの使い分け

`Hundred`は製品名、「ホーム」はHundred内の画面名として扱う。

| 用途 | 表記 |
| --- | --- |
| 製品全体の名称 | Hundred |
| 最初の画面、ナビゲーション名 | ホーム |
| ソースコードや設計上の識別名 | HundredHome |

`Hundred Home`を独立した正式ブランド名として定義しない限り、ユーザー向けUIでは「ホーム」と表記する。

例:

| 避ける表記 | 採用する表記 |
| --- | --- |
| アカウントを選択してHomeを開始します | アカウントを選択してHundredを開始します |
| Back to Home | ホームに戻る |
| Home Settings | ホーム設定 |

## 7. 外来語の扱い

日本語として定着している外来語は、無理に漢字に置き換えずカタカナで表記する。

```text
ホーム
アプリ
プロフィール
ストア
サウンド
アカウント
```

日本語化とは、すべてを漢字に置き換えることではなく、日本語環境で一般的に理解される表記を使うことを意味する。

## 8. 装飾用の英語表記

見出しの上に`Settings`、`Profile`などを小さく表示するデザインは、装飾としての使用に限り認める。

その場合も、次の条件を満たすこと。

- 日本語の正式な見出しが別に存在する
- 英語表記が操作の理解に必要な唯一の情報になっていない
- 同種の画面で使用方法が統一されている
- スクリーンリーダーに不要な装飾は読み上げさせない

デザインの印象だけを理由に、操作名や状態を英語にしない。

## 9. アクセシビリティ

- `aria-label`は、日本語UIの内容に合わせて日本語で記述する。
- 画面上の表記と`aria-label`で、異なる用語を使わない。
- 固有名詞は画面上と同じ正式表記にする。
- 「ボタン」などの要素の種類は、スクリーンリーダーが自動的に読み上げる場合は重複して記述しない。

例:

```tsx
<button aria-label="通知設定を閉じる" />
```

## 10. 用語の統一

1つの概念に複数の表記を使わない。

| 採用する表記 | 避ける表記 |
| --- | --- |
| ホーム | Home、ホーム画面※ |
| アプリ | Apps、アプリケーション |
| メールアドレス | Email、E-mail、メアド |
| 通知 | Notification、Notifications、お知らせ※ |
| サインイン | Sign in、Sign-in、ログイン |

※文脈上、「ホーム画面」と明記する必要がある場合や、通知とお知らせが異なる機能を指す場合は例外とする。

新しい用語を追加する際は、既存画面で同じ概念が使われていないか確認する。用語の判断が今後も発生する場合は、本ファイルの対応表を用語集として更新する。

## 11. 実装時のルール

- 同じ文言を複数箇所で使う場合は、定数またはメッセージリソースで管理する。
- UI文言と内部識別子を分離する。内部IDが`settings`であっても、表示名は「設定」とする。
- ユーザーや外部サービスが登録した名称は、原則として翻訳しない。
- 将来の多言語対応を考慮し、文の一部だけを差し替える文字列連結は避ける。

## 12. レビュー時の確認項目

- 操作名、機能名、状態が日本語になっているか
- 英語を残す場合、本ルールの例外条件に該当するか
- 固有名詞の大文字、小文字、スペースが正式表記と一致しているか
- 同じ概念に別の用語を使っていないか
- ボタンの文言から、押した後の結果を予測できるか
- 説明文を読まなくても、主要な操作を理解できるか
- `aria-label`などのアクセシビリティ用テキストも日本語で統一されているか
