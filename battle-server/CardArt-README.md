# 保存デッキから引いたカードの画像表示

実装済み・ビルドと動作確認は未実施です。

今回の経路は「公開マスターの画像キー → 保存デッキ → バトルのカード情報 → Unityが必要時にHTTP取得 → カードUIへの合成」です。対戦のカード一覧から開きます。手札・場の一覧自体を画像UIへ置き換える変更ではありません。

## 起動

既存のホームとバトルをCtrl+Cで停止します。プロジェクトで次を実行してください。

```bash
cd /Users/yama/Workspace/hundred
bash scripts/card-home-poc.sh art-init
bash scripts/card-home-poc.sh art-start
```

`art-init` は公開マスター `poc-art-001` を追加します。既存の `poc-001` と保存デッキは保持します。初回の通常 `init` が完了済みであることが前提です。

ホーム `http://127.0.0.1:8788` を再読み込みし、公開マスターが `poc-art-001` になっていることを確認してください。40枚を選び、新しいデッキを保存してIDをコピーします。このバージョンの初期デッキは自動生成しません。

別ターミナルで実行します。

```bash
cd /Users/yama/Workspace/hundred
bash scripts/card-battle-poc.sh build
bash scripts/card-battle-poc.sh start
```

両プレイヤーとも今回保存したデッキIDを使い、ルームを作成・参加してください。旧 `deck-poc` では画像参照が空のため画像は出ません。

## 確認

1. 初期手札から「カード一覧・詳細」を開き、カードを選択して「画像付きカードを開く」を押す。
2. 名前・コスト・レベル・BPが選んだカードと一致する。画面右に軽減とシンボルの値も表示する。英語名はマスターにないためカードIDで代用する。
3. 赤のカードはゴラドンの画像、紫はウィル・オーブの画像が表示される。これらは既存の仮カードへ割り当てた検証素材で、原作カードの性能への変更ではない。
4. 一覧へ戻り、同じ画像を使うカードを再び開く。「メモリキャッシュから表示」となる。同一URLの画像を共有し、最大8枚までメモリに保持する。
5. 引いたカードを召喚し、自分の場と相手側の公開された場からも同じカードを開ける。相手の手札と山札は閲覧対象へ追加していない。
6. 緑のカード `POC-016` を含むデッキでは、そのカードを引いて開くと「画像未登録」となる。カード情報の閲覧と対戦は継続できる。緑用の装飾枠は未作成なので簡易表示になる。
7. 画像取得失敗時はエラーを表示し、一覧へ戻って開き直すと再試行する。取得中に閉じるとリクエストを中断する。

対戦データは閲覧中も同期します。画像画面の数値は開いた時点のカード定義です。防御操作には画面を閉じて盤面に戻ります。

## 今回の範囲

- ローカルの `battle-server/card-art/` を `/card-art/` でHTTP配信。R2/CDNへの移行前の代替です。
- マスターにはURLではなく `cards/poc/goradon/v1.png` のようなObject Keyを保存。バージョンを含むパスは上書きせず、差し替えは新しいキーで行います。
- 今回は既存PNGを使い、WebPの変換品質・デコード互換性・R2・別オリジンCORSは検証していません。
- HTTPレスポンスは長期キャッシュ設定ですが、ブラウザキャッシュの実動作は開発者ツールで別途確認が必要です。画面のキャッシュ表示はUnity内のメモリキャッシュを指します。
- ロビーのカード表示試作は維持しているため、その試作用画像は引き続きResourcesに含まれます。WebGLの初回配信サイズ削減まで完了したものではありません。
- 旧バージョンで検証を再開する場合はホームを停止し、通常の `bash scripts/card-home-poc.sh start` を使用します。
